# Berserk VPN — نسخه ۵ (تیکت + بک‌آپ + پنل مخفی + پیام‌های سفارشی)

این نسخه روی v4 (کیف پول + تنظیمات بدون کدنویسی + رفع ۵ مشکل پایداری)
ساخته شده و ۶ قابلیت جدید اضافه کرده.

## 🆕 چی جدیده

### 1️⃣ پنل ادمین مخفی (بدون `/admin`)
`/admin` دیگه کار نمی‌کنه. دو راه جدید برای باز کردن پنل:
- یه دستور مخفی با اسم دلخواه شما، از طریق متغیر محیطی `ADMIN_COMMAND`
  (مثلا `panel_x7k9`) — **حتما این رو در Railway تنظیم کنید**، وگرنه با
  مقدار پیش‌فرض `panel_secret` می‌مونه و امنیتش کم میشه (ربات موقع
  استارت هم یه هشدار لاگ می‌کنه اگه یادتون بره عوضش کنید)
- یه دکمه «🛠 مدیریت» که فقط توی منوی اصلی خود شما (بر اساس آیدی عددی)
  دیده میشه؛ کاربرای عادی اصلا این دکمه رو نمی‌بینن

### 2️⃣ هشدار خودکار موجودی کم
بعد از هر فروش چک میشه؛ اگه موجودی لینک به آستانه‌ای که تعیین می‌کنید
(پیش‌فرض ۵، از پنل تنظیمات قابل تغییره) برسه، به همه ادمین‌ها پیام هشدار
می‌ره. برای جلوگیری از اسپم، فقط یه‌بار هشدار می‌ده تا دوباره لینک اضافه
کنید (اضافه‌کردن لینک جدید خودکار فلگ هشدار رو ریست می‌کنه).

### 3️⃣ جلوگیری از رسید تکراری
هر عکس رسید با `file_unique_id` تلگرام (که برای همون عکس فیزیکی همیشه
ثابته، حتی اگه دوباره فوروارد بشه) ردیابی میشه. اگه یه عکس قبلا به‌عنوان
رسید فرستاده شده باشه، پیامی که برای شما میره با یه هشدار واضح شروع میشه:
«⚠️ این عکس قبلا X بار به‌عنوان رسید فرستاده شده — احتمال تقلب».

### 4️⃣ بک‌آپ خودکار + دستی + بازگردانی
- **خودکار:** هر ۲۴ ساعت، فایل دیتابیس مستقیم توی تلگرام برای همه
  ادمین‌ها فرستاده میشه
- **دستی:** دکمه «📥 دریافت بک‌آپ» توی پنل — همون لحظه یه بک‌آپ تازه
  می‌گیره و می‌فرسته
- **بازگردانی:** دکمه «📤 بارگذاری بک‌آپ» — فایل `.db` رو می‌فرستید، فورا
  (طبق خواسته شما بدون تاییدیه اضافه) جایگزین دیتابیس فعلی میشه

⚠️ **نکات مهم درباره بازگردانی:**
- قبل از هر بازگردانی، یه نسخه امن از دیتابیس *فعلی* (قبل از جایگزینی)
  خودکار نگه داشته میشه، با اسمی مثل `berserk_pre_restore_TIMESTAMP.db`
  — اگه اشتباهی فایل غلط آپلود کردید، از همینجا قابل برگردوندنه (دستی،
  از طریق SSH/Railway)
- فایل آپلودشده قبل از جایگزینی اعتبارسنجی میشه (باید واقعا یه دیتابیس
  SQLite با جدول‌های `users` و `subs` باشه)، پس آپلود یه فایل نامعتبر
  چیزی رو خراب نمی‌کنه
- بعد از یه بازگردانی موفق، **ربات عمدا خودش رو می‌بنده** تا با دیتابیس
  تازه از نو بالا بیاد؛ برای همین `railway.json` رو به `restartPolicyType:
  ALWAYS` تغییر دادم — این یعنی Railway خودش خودکار دوباره روشنش می‌کنه
  (چند ثانیه طول می‌کشه). روی VPS بدون یه process manager (مثل
  `systemd` یا `pm2`)، این ری‌استارت خودکار اتفاق نمی‌افته — حتما یکی از
  این‌ها رو تنظیم کنید

### 5️⃣ سیستم تیکت پشتیبانی
- مشتری روی «🎫 پشتیبانی» می‌زنه، پیامش (متن/عکس/فایل - هرچی) رو
  می‌فرسته
- برای همه ادمین‌ها با یه سربرگ «🎫 تیکت جدید #ID» فرستاده میشه
- **برای پاسخ، فقط روی همون پیام ریپلای کنید** — ربات خودکار تشخیص میده
  این تیکت مال کدوم مشتریه و جوابتون رو مستقیم براش می‌فرسته. نیازی به
  دستور یا فرم اضافه نیست
- توی پنل، «🎫 تیکت‌های باز» لیست تیکت‌های بازو نشون میده با دکمه «بستن»

### 6️⃣ پیام‌های قابل‌ویرایش با عکس/بنر
از پنل → «🖼 ویرایش پیام‌ها»، این ۴ صفحه قابل شخصی‌سازی‌ان:
- پیام خوش‌آمد (بعد از `/start`)
- صفحه خرید
- صفحه کیف پول
- صفحه دعوت دوستان

**نکته طراحی مهم:** قیمت، موجودی، و مبلغ کیف‌پول همیشه باید دقیق و زنده
باشن، پس این‌ها نمی‌تونن با یه متن ثابت جایگزین بشن. برای همین سیستم یه
«بنر/مقدمه» اختیاری (متن + عکس) *قبل از* متن دینامیک اصلی نشون می‌ده —
یعنی هم برندینگ دلخواهتون رو دارید، هم عددها همیشه درستن. برای هر صفحه:
- فقط متن بفرستید → فقط بنر متنی عوض میشه
- یه عکس بفرستید (با یا بدون کپشن) → عکس (و در صورت وجود کپشن، متن) عوض میشه
- `/clear` بفرستید → بنر اون صفحه پاک میشه و برمی‌گرده به حالت پیش‌فرض (بدون بنر)

## ✅ تست‌هایی که واقعا اجرا شدن
همه این‌ها با کد واقعی (نه فقط syntax check) تست شدن:
- Import کامل با aiogram 2.25.1 واقعی
- تشخیص رسید تکراری (همون عکس، کاربر متفاوت)
- ریست خودکار فلگ هشدار موجودی کم بعد از افزودن لینک جدید
- ساخت تیکت، نگاشت پیام ادمین به تیکت/مشتری، بستن تیکت
- تنظیم/حذف بنر پیام سفارشی
- ساخت فایل بک‌آپ با `Connection.backup()` و بررسی محتوای واقعیش
- اعتبارسنجی فایل نامعتبر (رد میشه) در مقابل فایل معتبر (قبول میشه)
- **سناریوی کامل بازگردانی:** بک‌آپ گرفتن از حالت A → تغییر دیتابیس به
  حالت B → بازگردانی با بک‌آپ A → باز کردن یه کانکشن کاملا تازه (شبیه‌سازی
  ری‌استارت واقعی) → تایید اینکه دقیقا حالت A برگشته، و نسخه امن قبل از
  بازگردانی دقیقا حالت B رو نگه داشته
- تست رگرسیون کامل جریان کسب‌وکار قبلی (شارژ → تایید → خرید → پاداش
  رفرال) برای اطمینان از اینکه هیچ‌کدوم از فیچرهای جدید چیزی رو خراب نکردن

## 📁 فایل‌های جدید نسبت به v4
```
backup.py     # بک‌آپ خودکار/دستی + بازگردانی امن
tickets.py    # سیستم تیکت پشتیبانی (پاسخ با ریپلای)
messages.py   # پیام‌های قابل‌ویرایش با بنر/عکس
.gitignore    # جلوگیری از commit شدن berserk.db و بک‌آپ‌ها
```
`bot.py`, `admin.py`, `wallet.py`, `subs.py`, `db.py`, `settings.py`,
`config.py`, `railway.json` همگی به‌روزرسانی شدن.

## متغیرهای محیطی (تغییر نسبت به v4)
| نام | الزامی | توضیح |
|---|---|---|
| `BOT_TOKEN` | ✅ | توکن از @BotFather |
| `ADMIN_ID` | ✅ | آیدی عددی ادمین؛ چند ادمین با کاما: `111,222` |
| `ADMIN_COMMAND` | 🆕 توصیه‌شده | اسم دستور مخفی پنل ادمین (پیش‌فرض ناامن: `panel_secret` — حتما عوضش کنید) |
| `MAX_TOTAL_REFERRALS` | خیر (پیش‌فرض ۵۰) | سقف کل رفرال هر معرف |
| `MAX_REFERRALS_PER_DAY` | خیر (پیش‌فرض ۱۰) | سقف روزانه پاداش رفرال |

## اجرا محلی
```bash
pip install -r requirements.txt
export BOT_TOKEN="توکن شما"
export ADMIN_ID="آیدی عددی شما"
export ADMIN_COMMAND="panel_x7k9"   # یه اسم دلخواه و غیرقابل‌حدس بذارید
python bot.py
```

## دیپلوی روی Railway
1. فایل‌ها رو جایگزین نسخه قبلی کنید و push کنید
2. حتما `ADMIN_COMMAND` رو با یه مقدار دلخواه در Variables تنظیم کنید
3. مطمئن بشید یه **Volume** به پروژه وصله (برای اینکه دیتابیس با
   ری‌دیپلوی از بین نره)
4. `restartPolicyType` توی `railway.json` به `ALWAYS` تغییر کرده — این
   لازمه تا فرآیند بازگردانی درست کار کنه

## گام بعدی پیشنهادی
شکاف‌های ساختاری بزرگ‌تری که قبلا تحلیل کردم هنوز باز هستن: اتصال به یه
پنل VPN واقعی (که گفتید فعلا نیاز ندارید)، درگاه پرداخت آنلاین (که گفتید
فعلا نیاز ندارید)، و چند سطح دسترسی ادمین (اگه بعدا بخواید یه اپراتور
جدا از خودتون داشته باشید). هر وقت خواستید روی یکی از این‌ها ادامه بدیم
بگید.
