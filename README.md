# Berserk VPN Bot v6.5.0 — Admin Users & Reports UX Upgrade


نسخه v6.5.0 یک ارتقای رابط و تحلیل مدیریتی روی سورس کامل v6.4.1 است. این نسخه منطق مالی، تحویل Provider، صف سفارش، دیتابیس کاربران و مسیر خرید مشتری را تغییر نمی‌دهد و Schema همچنان 640 است.

## مرکز جدید کاربران و گزارش‌ها در v6.5.0

- داشبورد خلاصه کاربران با تعداد واقعی، خریداران، سرویس‌ها، فعالیت و موارد نیازمند پیگیری
- خلاصه هوشمند ۷/۳۰ روزه همراه با پیشنهاد عملی
- ۱۴ گروه خودکار و صفحه‌بندی ۶تایی کاربران
- پیام هدفمند مستقیم برای گروه‌های مجاز؛ کاربران بن‌شده ارسال نمی‌گیرند و گروه‌های تجاری کاربران تست را حذف می‌کنند
- داشبورد گزارش‌ها با فروش، کاربران، سرویس‌ها، پرداخت‌ها، پشتیبانی و قیف خرید
- دکمه‌های بازگشت و جایگاه منوها بازتنظیم شده‌اند تا مدیر در مسیر درست باقی بماند

مسیرهای جدید:

```text

پنل مدیریت → گزارش‌ها → فروش / کاربران / سرویس‌ها / پرداخت‌ها / پشتیبانی / قیف خرید
```

## Hotfix v6.4.1

- رفع `ProviderError has no attribute code` در مسیر اکانت تست.
- ثبت کد `already_claimed` برای درخواست تست تکراری.
- محدودکردن متن `answerCallbackQuery` به کمتر از ۲۰۰ کاراکتر و جلوگیری از `Message_too_long`.
- تبدیل خطاهای 502/503/504 و Cloudflare 520 تا 526 به پیام کوتاه «پنل موقتاً در دسترس نیست».
- تنظیم Polling با `timeout=30`، `relax=1.0` و `fast=False` برای کاهش فشار هنگام خطاهای موقت شبکه.
- ارسال لاگ‌های Python به stdout تا Railway پیام‌های INFO را با برچسب err نمایش ندهد.

> این نسخه تغییر دیتابیس ندارد و Migration جدیدی اجرا نمی‌کند.

## هشدار امنیتی

اطلاعات زیر را هرگز داخل سورس، GitHub، README، لاگ یا پیام تلگرام قرار ندهید:

- رمز پنل
- JWT / Bearer Token
- توکن ربات
- Cookie یا Session
- لینک اشتراک واقعی مشتری

اطلاعات محرمانه فقط در Railway Variables نگهداری شوند. JWT پنل فقط در حافظه Process نگهداری می‌شود و وارد SQLite یا بک‌آپ نمی‌شود.

اگر توکن یا رمز قبلاً منتشر شده است، رمز را تغییر دهید و نشست‌های قبلی را باطل کنید.

## اتصال تأمین‌کننده YouPanel

YouPanel در v6.3 یک Adapter از سیستم عمومی Provider است؛ یعنی پلن‌های فروشگاه با `provider_key` به تأمین‌کننده متصل می‌شوند و منطق خرید به نام YouPanel گره نخورده است.

### متغیرهای اتصال

```env
YOUPANEL_BASE_URL=https://panel.example.com:2053
YOUPANEL_USERNAME=panel_admin_username
YOUPANEL_PASSWORD=panel_admin_password
YOUPANEL_TIMEOUT_SECONDS=20
YOUPANEL_VERIFY_SSL=true
YOUPANEL_INBOUNDS_JSON={"vless":["RTL-1","VLESS + WS","tcp","TUN"]}
```

آدرس پایه نباید `/dashboard` یا `/api` داشته باشد. نام inboundها باید دقیقاً با پنل برابر باشند.

### APIهای استفاده‌شده توسط Adapter فعلی

```text
POST   /api/admin/token
POST   /api/user
PUT    /api/user/{username}
DELETE /api/user/{username}
GET    /api/user/{username}/usage?start=...
POST   /api/user/{username}/reset
POST   /api/user/{username}/revoke_sub
GET    /api/admin
```

API مشاهده‌شده داخلی پنل است و ممکن است پس از ارتقای پنل تغییر کند. بعد از هر آپدیت YouPanel ابتدا در محیط تست، `تأمین‌کننده‌ها → YouPanel → تست اتصال` را اجرا کنید.

## روش‌های خرید هر پلن

### خرید مستقیم (`direct`)

- فقط یک سرویس خریداری می‌شود
- مرحله انتخاب تعداد حذف می‌شود
- مناسب سرویس اختصاصی یا پلن‌های شخصی

### انتخاب تعداد (`quantity`)

- دکمه‌های تعداد تا سقف پلن نشان داده می‌شوند
- مناسب استخر لینک یا خرید چند سرویس

### عمده (`wholesale`)

- خرید خودکار بسته است
- کاربر به هماهنگی پشتیبانی/عمده هدایت می‌شود

### غیرفعال (`disabled`)

- پلن در فروشگاه قابل خرید نیست

---

## روش‌های تحویل

### استخر (`pool`)

- لینک‌ها پیش از فروش به همان پلن وارد می‌شوند
- تخصیص لینک و کسر کیف پول اتمیک است
- لینک تکراری وارد نمی‌شود
- لینک تحویل اشتباه قابل بازگردانی به همان استخر است

### تأمین‌کننده (`provider`)

- سرویس پس از پرداخت ساخته می‌شود
- هر خرید یک provider key ذخیره می‌کند
- در موفقیت، subscription URL ذخیره و تحویل می‌شود
- در شکست، ساخت‌های نیمه‌کاره best-effort پاک و مبلغ Refund می‌شود
- سفارش provisioning قدیمی پس از Restart بازیابی می‌شود

Providerهای ثبت‌شده از طریق Registry در `subs.py` مدیریت می‌شوند. افزودن پنل جدید باید با پیاده‌سازی Interface مشترک انجام شود، نه با تغییر مستقیم مسیر خرید و کیف پول.

## دیتابیس و Migration

Schema نسخه حاضر:

```text
640
```

جدول‌ها/فیلدهای مهم v6.3:

- `provider_states` و `provider_logs`
- `provider_jobs` و `provider_job_items`
- `discounts` و `discount_redemptions`
- `campaigns` و `campaign_deliveries`
- `plan_text_templates`
- `plans.fallback_provider_key` و `plans.template_id`
- `plan_categories.template_id`
- فیلدهای Retry، تخفیف، Notification و Review در `purchases`
- Snapshot سرویس در `tickets`

Migration پلن‌های قدیمی:

- عنوان دارای VIP/ویژه → دسته VIP
- عنوان دارای اقتصادی/economic → دسته اقتصادی
- سایر پلن‌ها → دسته سرویس‌ها
- `delivery_type=youpanel` به provider key مربوطه منتقل می‌شود
- فروش استخری و خریدهای قبلی حفظ می‌شوند

قبل از Deploy از دیتابیس فعلی بک‌آپ بگیرید. Restore بک‌آپ با Schema جدیدتر از سورس فعلی رد می‌شود.

## تست و Deploy

ترتیب تست پیشنهادی:

1. بک‌آپ دیتابیس فعلی
2. Redeploy سورس v6.4
3. بررسی Migration تا Schema 640
4. تست خرید مستقیم و تعدادی بدون کد تخفیف
5. تست کد تخفیف و خرید پس از شارژ هدفمند
6. توقف موقت Provider و بررسی پیام عدم دسترسی یا Failover
7. ایجاد خطای کنترل‌شده و بررسی Retry، صف و Refund یک‌باره
8. ثبت گزارش مشکل برای یک سرویس و بررسی Snapshot ادمین
9. بررسی گزارش پلن، دسته، تست و مشتریان
10. ساخت/کپی/تخصیص/Restore قالب متن
11. بررسی بک‌آپ و Restore روی محیط تست

تست مخرب با پنل واقعی، پرداخت واقعی و توکن واقعی تلگرام داخل محیط ساخت این ZIP انجام نشده است.

## محدودیت‌های فعلی

- Provider عملیاتی موجود فعلاً YouPanel است؛ معماری برای Adapterهای بعدی آماده شده است.
- پروژه روی `aiogram 2.25.1` و Python 3.11 اجرا می‌شود.
- SQLite برای یک Instance مناسب است؛ اجرای چند Replica هم‌زمان به PostgreSQL نیاز دارد.
- بدون API پنل، مصرف واقعی و اولین اتصال سرویس‌های استخری قابل تشخیص نیست.
- برای جلوگیری از شلوغ‌شدن فایل‌های قدیمی، منطق تجاری v6.3 در `commerce.py` و رابط‌های آن در `v63_handlers.py` جدا شده‌اند.
