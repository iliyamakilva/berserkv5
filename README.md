# Berserk VPN Bot v6.1.1 — YouPanel Device Limits

ربات تلگرام فروش VPN با دو روش تحویل هم‌زمان:

1. **استخر لینک آماده** برای ساب‌لینک‌هایی که از تأمین‌کننده خریداری و وارد دیتابیس می‌شوند.
2. **ساخت خودکار YouPanel** برای ایجاد سرویس اختصاصی با حجم و مدت مشخص پس از خرید.

این نسخه ساختار اصلی **۲۲ فایلی** پروژه را حفظ می‌کند و قابلیت ساخت خودکار سرویس، اکانت تست، مشاهده مصرف، صفرکردن مصرف، تعویض لینک و حذف سرویس پنلی را به نسخه تمیزشده v6.0.0 اضافه می‌کند.

---

## هشدار امنیتی قبل از نصب

اطلاعات ورود پنل و JWT را داخل سورس، GitHub، دیتابیس، README یا لاگ قرار ندهید. فقط از Environment Variables استفاده کنید.

اگر JWT یا رمز پنل قبلاً در تصویر یا پیام منتشر شده است:

1. از پنل Logout کنید.
2. رمز پنل را تغییر دهید.
3. نشست‌های قبلی را در صورت امکان Revoke کنید.
4. فقط اطلاعات جدید را در Railway Variables قرار دهید.

توکن Bearer در این پروژه فقط در حافظه Process نگهداری می‌شود و در SQLite یا بک‌آپ ذخیره نمی‌شود.

## نصب روی Railway

متغیرهای الزامی ربات:

```env
BOT_TOKEN=توکن ربات از BotFather
ADMIN_ID=آیدی عددی ادمین یا چند آیدی جداشده با کاما
ADMIN_COMMAND=دستور مخفی پنل مدیریت
DB_PATH=/data/berserk.db
```

متغیرهای پیشنهادی عمومی:

```env
OWNER_ID=آیدی مالک اصلی برای عملیات حساس
BROADCAST_DELAY=0.08
REF_REWARD=30000
MAX_TOTAL_REFERRALS=50
MAX_REFERRALS_PER_DAY=10
BACKUP_INTERVAL_SECONDS=86400
BACKUP_RETENTION_COUNT=30
```

### تنظیم اتصال YouPanel

```env
YOUPANEL_BASE_URL=https://panel.example.com:2053
YOUPANEL_USERNAME=panel_admin_username
YOUPANEL_PASSWORD=panel_admin_password
YOUPANEL_TIMEOUT_SECONDS=20
YOUPANEL_VERIFY_SSL=true
```

Inboundهای مجاز پنل به‌صورت JSON:

```env
YOUPANEL_INBOUNDS_JSON={"vless":["RTL-1","VLESS + WS","tcp","TUN"]}
```

نام inboundها باید دقیقاً با نام‌های موجود در پنل شما یکی باشد. در صورت تغییر نودها یا inboundها، این Variable را نیز به‌روزرسانی کنید.

تنظیم اکانت تست:

```env
YOUPANEL_TRIAL_ENABLED=true
YOUPANEL_TRIAL_SIZE_MB=200
YOUPANEL_TRIAL_DAYS=1
YOUPANEL_TRIAL_MAX_DEVICES=1
```

برای دیتابیس دائمی، Railway Volume بسازید و `DB_PATH` را روی مسیر Volume تنظیم کنید. فایل دیتابیس را هنگام جایگزینی سورس overwrite نکنید.

Runtime:

```txt
Python 3.11.9
aiogram 2.25.1
SQLite
YouPanel HTTP API
```

## مدل ترکیبی تحویل سرویس

هر پلن دارای `delivery_type` است:

```txt
pool       تحویل از استخر لینک آماده

youpanel   ساخت خودکار کاربر در YouPanel
```

### پلن استخری

- قبل از فروش باید لینک‌های آماده همان پلن وارد شوند.
- موجودی آزاد کنترل می‌شود.
- خرید و تخصیص لینک داخل تراکنش SQLite انجام می‌شود.
- سرویس تحویل‌شده را ادمین می‌تواند به همان استخر برگرداند.

### پلن YouPanel

- لینک دستی به آن وارد نمی‌شود.
- پس از خرید، ربات کاربر اختصاصی در پنل می‌سازد.
- حجم، مدت، نوع شروع اعتبار و محدودیت دستگاه از تنظیمات همان پلن خوانده می‌شود.
- `subscription_url` برگشتی در دیتابیس ذخیره و همراه QR برای مشتری ارسال می‌شود.
- موجودی آن وابسته به سهمیه کل پنل است، نه جدول استخر لینک.

## ساخت پلن YouPanel از پنل ادمین

مسیر:

```txt
پنل مدیریت
→ 📦 سرویس‌ها و پلن‌ها
→ 🏷 مدیریت پلن‌ها
→ ➕ ساخت سریع پلن
```

در ویزارد، پس از عنوان، حجم نمایشی، مدت نمایشی، قیمت و توضیح، روش تحویل را انتخاب کنید:

```txt
📦 تحویل از استخر لینک
⚡ ساخت خودکار از YouPanel
```

برای پلن خودکار این فیلدها گرفته می‌شود:

- حجم پنلی، مانند `50GB` یا `200MB`
- مدت پنلی بر حسب روز
- شروع اعتبار از زمان ساخت یا از اولین اتصال
- تعداد دستگاه مجاز: ۱، ۲، ۳ یا بدون محدودیت
- Reset strategy، پیش‌فرض `no_reset`

### شروع از زمان ساخت

```txt
status = active
expire = زمان فعلی + مدت پلن
```

### شروع از اولین اتصال

```txt
status = on_hold
expire = null
on_hold_expire_duration = مدت پلن بر حسب ثانیه
```

برای بیشتر پلن‌های مشتری، شروع از اولین اتصال مناسب‌تر است.

## جریان خرید پنلی

```txt
انتخاب پلن YouPanel
→ انتخاب تعداد
→ بررسی تنظیمات پنل و پلن
→ بررسی کیف پول
→ رزرو خرید و کسر موقت مبلغ
→ ساخت کاربر/کاربران با username قطعی و یکتا
→ دریافت subscription_url
→ ثبت سرویس‌ها در SQLite
→ تکمیل خرید و ارسال لینک و QR
```

نام کاربری پنل بر اساس شناسه کاربر و شماره خرید ساخته می‌شود تا Retry باعث ساخت سرویس تکراری نشود.

اگر API پنل خطا بدهد:

- ربات تلاش می‌کند اکانت‌های نیمه‌ساخته را پاک کند.
- مبلغ خرید به کیف پول برمی‌گردد.
- خرید `failed` می‌شود و خطا ثبت می‌شود.
- اگر Process وسط ساخت متوقف شود، هنگام Startup سفارش‌های پنلی قدیمی در وضعیت `provisioning` بازیابی و refund می‌شوند.

این طراحی از کم‌شدن پول بدون تحویل سرویس جلوگیری می‌کند.

## اکانت تست خودکار

دکمه سیستمی جدید:

```txt
🧪 اکانت تست
```

قواعد:

- فقط وقتی YouPanel تنظیم شده و Trial فعال باشد نمایش داده می‌شود.
- هر Telegram ID فقط یک بار می‌تواند تست بگیرد.
- نام کاربری پنل به‌صورت قطعی از Telegram ID ساخته می‌شود.
- حجم، مدت و تعداد دستگاه مجاز از Environment خوانده می‌شوند.
- اعتبار تست از اولین اتصال شروع می‌شود.
- مقدار پیش‌فرض تست یک دستگاه است.
- لینک و QR مستقیم برای کاربر ارسال می‌شوند.
- تست در `trial_claims` و جدول سرویس‌ها ثبت می‌شود.
- در صورت شکست ساخت، رکورد به `failed` می‌رود و کاربر بعداً می‌تواند دوباره تلاش کند.

اکانت تست رایگان با «کاربر تست» مدیریتی متفاوت است:

- **اکانت تست رایگان:** سرویس پنلی یک‌بارمصرف برای مشتری.
- **وضعیت کاربر تست:** برچسب مدیریتی برای حذف خریدهای آزمایشی ادمین از گزارش فروش واقعی.

## مدیریت سرویس پنلی از ادمین

در جزئیات یک سرویس YouPanel، عملیات زیر نمایش داده می‌شوند:

```txt
📊 مشاهده مصرف
♻️ صفر کردن مصرف
🔄 تعویض لینک اشتراک
🗑 حذف سرویس از پنل
```

### مشاهده مصرف

مصرف تفکیکی نودها از API دریافت و مصرف کل در دیتابیس محلی همگام می‌شود.

### صفرکردن مصرف

پس از تأیید دومرحله‌ای، مصرف کاربر پنل صفر می‌شود. حجم، مدت و لینک تغییر نمی‌کنند.

### تعویض لینک اشتراک

شناسه دسترسی و `subscription_url` جدید دریافت می‌شود. لینک قبلی باطل شده و لینک جدید در دیتابیس جایگزین می‌شود. امکان ارسال مجدد لینک و QR به مشتری باقی می‌ماند.

### حذف سرویس

کاربر از YouPanel حذف و رکورد محلی به وضعیت `deleted` منتقل می‌شود. این سرویس به استخر لینک برنمی‌گردد و refund خودکار ندارد؛ حذف یک اقدام مدیریتی مستقل است.

تمام عملیات حساس در `admin_logs` ثبت می‌شوند.

## APIهای استفاده‌شده

اتصال بر اساس API مشاهده‌شده YouPanel v0.9.0 پیاده‌سازی شده است:

```txt
POST   /api/admin/token
POST   /api/user
DELETE /api/user/{username}
GET    /api/user/{username}/usage?start=...
POST   /api/user/{username}/reset
POST   /api/user/{username}/revoke_sub
GET    /api/admin
```

ورود با فرم زیر انجام می‌شود:

```txt
username
password
grant_type=password
```

پاسخ Login شامل `access_token` و `token_type=bearer` است. در خطای 401، ربات یک‌بار دوباره Login و درخواست را Retry می‌کند.

این API داخلی ممکن است در نسخه‌های بعدی YouPanel تغییر کند. پس از ارتقای پنل، ابتدا روی محیط تست بررسی شود.

## دیتابیس و Migration

Schema فعلی:

```txt
610
```

مهم‌ترین افزوده‌ها:

- تنظیمات منبع تحویل و مشخصات پنلی در جدول `plans`
- اطلاعات provider، username، status، حجم، مصرف و انقضا در `subs`
- provider، خطای Provisioning و زمان‌های تکمیل/refund در `purchases`
- جدول `trial_claims`
- index یکتا برای `panel_username`

Migration از v6.0.0/Schema 600 خودکار است. داده‌های قدیمی به‌عنوان `pool` طبقه‌بندی می‌شوند و مسیر قبلی فروش بدون تغییر باقی می‌ماند.

## قواعد مالی و هم‌زمانی

- خرید استخری داخل `BEGIN IMMEDIATE` انجام می‌شود.
- خرید پنلی ابتدا یک سفارش `provisioning` و کسر کیف پول ثبت می‌کند.
- تکمیل فقط بعد از دریافت تمام لینک‌ها انجام می‌شود.
- شکست ساخت باعث refund اتمیک و ledger با action برابر `purchase_refund` می‌شود.
- سفارش completed یا refunded دوباره تغییر وضعیت نمی‌دهد.
- username قطعی، retry ساخت را idempotent‌تر می‌کند.
- Trial با Unique Constraint فقط یک بار برای هر user_id ثبت می‌شود.

برای اجرای چند Replica هم‌زمان، SQLite انتخاب ایده‌آلی نیست؛ یک Replica نگه دارید یا در آینده به PostgreSQL و Job Queue مهاجرت کنید.

## بک‌آپ و Restore

بک‌آپ شامل تمام تنظیمات پلن، سرویس‌های پنلی، Trial claims و سوابق Provisioning است؛ اما رمز پنل و JWT داخل آن نیستند.

قبل از Restore بررسی می‌شود:

- SQLite و `PRAGMA integrity_check`
- جدول‌ها و ستون‌های ضروری
- نسخه Schema
- آمار اصلی
- جدیدتر نبودن Schema بک‌آپ از سورس

قبل از Restore، Safety Backup ساخته می‌شود.

- `python -m py_compile` برای تمام فایل‌های Python
- init دیتابیس با Schema 610

تست زنده destructive با پنل واقعی، توکن واقعی تلگرام یا پرداخت واقعی انجام نشده است. ابتدا پلن کوچک و کاربر تست بسازید.

## چک‌لیست تست بعد از Deploy

1. از دیتابیس فعلی بک‌آپ بگیرید.
2. رمز پنل را در صورت افشای قبلی عوض کنید.
3. Variables مربوط به YouPanel را در Railway قرار دهید.
4. Redeploy کنید.
5. از پنل ادمین «تست اتصال YouPanel» را اجرا کنید.
6. یک پلن خودکار ۲۰۰MB یک‌روزه بسازید.
7. با کاربر تست خرید کنید و لینک/QR را بررسی کنید.
8. Usage، Reset و Revoke را روی همان سرویس تست کنید.
9. حذف سرویس را فقط روی حساب آزمایشی بررسی کنید.
10. دکمه اکانت تست را با یک Telegram ID آزمایشی اجرا کنید.
11. مسیر خرید استخری قدیمی را نیز جدا تست کنید.
12. بعد از تأیید همه موارد، فروش اصلی را باز کنید.

## محدودیت‌ها

- API استفاده‌شده داخلی YouPanel است و ممکن است با آپدیت پنل تغییر کند.
- نام inboundها به تنظیمات همان پنل وابسته‌اند.
- سهمیه کل پنل قبل از هر ساخت از endpoint اختصاصی رزرو نمی‌شود؛ خطای پنل باعث refund می‌شود.
- همگام‌سازی مصرف فعلاً هنگام درخواست ادمین انجام می‌شود، نه به‌صورت Cron دائمی.
- حذف سرویس پنلی refund خودکار ندارد.
- SQLite برای چند Process مناسب نیست.
- `aiogram 2.25.1` قدیمی است و مهاجرت آن باید نسخه مستقل باشد.
